# 📦 Где что лежит — Мобильная система учета и поиска по складу

Современное веб-приложение на Streamlit для оперативного поиска ТМЦ, основных
средств, пластика для 3D-печати и расходных материалов на складе.

Приложение работает в **двух режимах**:

- **Excel-режим** — читает данные из локального файла или с Яндекс.Диска
  (read-only).
- **PostgreSQL-режим** — полноценная работа с базой данных: поиск, аналитика,
  CRUD для всех 4 таблиц (Закупки, ОС Главная, Пластик, Настройки пластика),
  аутентификация и роли.

**Доступ к приложению** — только после входа (логин/пароль).

Источник переключается в сайдбаре. Интерфейс адаптирован как для компьютеров,
так и для мобильных устройств.

## 🚀 Основной функционал

### 1. 🔍 Поиск по складу
- **Многостраничный поиск:** быстрое переключение между листами реестра
  (Закупки, ОС Главная, Пластик) через `segmented_control`.
- **Умный нерегистрозависимый поиск:** мгновенный фильтр по наименованию,
  артикулу/коду, куратору или месту хранения. Для коротких токенов (PLA, ASA,
  №4) — поиск по границам слова, для длинных — с учётом окончаний.
- **Поиск по фрагменту кода:** если основной поиск не дал результатов, а запрос
  целиком цифровой — система пробует найти его как подстроку в колонках
  `Код` и `QR код`. Например, ввод `122` найдёт позицию с кодом
  `ОБ00000000122`.
- **Информативные карточки (`st.expander`):** статус, количество/остаток,
  проект, ячейка хранения, стоимость, QR-код, куратор, отдел МТО.
- **Пагинация результатов:** не более 50 карточек на страницу — быстро даже
  при поиске по общим терминам («пластик»).
- **Быстрые фильтры:** кнопки-чипы для типовых запросов (PLA, Принтер,
  Смирнова, Цех №4 и т.д.).
- **Специальный запрос:** `без места` — показать позиции без указанной ячейки.
- **Сводка до поиска:** метрики «Всего позиций» и «Занято ячеек» на главном
  экране.
- **Кнопки «Сброс» и «Обновить»:** очистка поиска и принудительное
  перечитывание данных из источника.

### 2. 📊 Аналитика и Отчеты
3 KPI и 2 интерактивных графика (Plotly Express) — индивидуально для каждого
листа склада:

- **Закупки:** успешность поставок, загрузка ячеек, средняя нагрузка на
  кураторов МТО; stacked-bar «статусы × кураторы» и donut-чарт распределения
  статусов.
- **ОС Главная:** коэффициент ввода в эксплуатацию, объём готовых к выдаче ОС,
  доля неинвентаризированных позиций; размещение по проектам и топ-5 самых
  затратных отделов МТО.
- **Пластик:** суммарный вес филамента в кг, катушки с критическим остатком
  (< 200 г), запасы по типам пластика и раскладка по брендам.

Аналитика корректно обрабатывает «грязные» числа из Excel (пробелы, валюта,
разные десятичные разделители — `1,234.56` и `1.234,56`), а также показывает
предупреждение, если часть значений не удалось распарсить.

### 3. 📷 Сканер QR-кодов
- **Загрузка и камера:** файл с телефона/ПК (поддерживается multi-upload) или
  снимок напрямую с веб-камеры.
- **Многоэтапное распознавание (OpenCV):** предобработка кадра (grayscale,
  CLAHE, адаптивный порог, Otsu thresholding) для считывания повреждённых и
  тусклых QR-кодов.
- **Авто-ресайз:** большие фото автоматически уменьшаются для быстрого
  отображения и распознавания на мобильных устройствах.
- **Быстрый переход:** распознавание прямых веб-ссылок с кнопкой мгновенного
  перехода.

### 4. 📁 Выбор источника данных
- Динамический селект в сайдбаре: **Яндекс.Диск**, **Локальный ПК**,
  **PostgreSQL** (если сконфигурирован).
- Рядом с каждым источником — индикатор статуса (✅ доступен / ⚠️ недоступен),
  размер файла и дата последней модификации.
- Кнопка «🔄 Проверить источники» для ручной перепроверки статусов.
- При переключении источника кеш данных автоматически сбрасывается — данные
  перечитываются «с нуля».
- **Excel-источники** (Я.Диск, Локальный ПК) — только чтение. Редактирование
  в них недоступно.
- **PostgreSQL** — полный доступ: чтение + CRUD.

### 5. 🖼️ Картинки товаров
- К карточке можно привязать **фото предмета** и **картинку QR-кода**.
- Связь — по значению колонки `Код`.
- Файлы лежат локально в папке, путь к которой задаётся в `.env`
  (`IMAGES_DIR`).
- **QR-коды генерируются автоматически** из значения колонки `QR код` — файл
хранить не нужно. Если для позиции есть готовый файл `<код>_qr.png`, он имеет
приоритет над генерацией (удобно, чтобы вручную «переопределить» QR).
Подробности — в разделе [«Генерация QR-кодов»](#-генерация-qr-кодов).
- Фото автоматически уменьшается для быстрого отображения на телефонах.
- Если фото или QR для позиции нет — показывается заглушка `no_photo.jpg`.

Подробности — в разделе [«Картинки товаров»](#-картинки-товаров).

### 6. ✏️ Редактирование (CRUD)

Полноценное редактирование данных доступно **только в режиме PostgreSQL**.
Раздел «Редактирование» в сайдбаре.

- **Добавление позиции:** форма со всеми полями (30 полей, сгруппированы
  по категориям: Идентификация, Финансы, Документы и т.д.). Обязательное
  поле — только `Код`.
- **Редактирование:** форма с предзаполненными полями. Работает
  **optimistic locking** — если кто-то изменил запись параллельно, при
  сохранении появится предупреждение.
- **Удаление:** мягкое (`is_deleted = TRUE`). Позиция скрывается из поиска
  и аналитики, но остаётся в БД (можно восстановить вручную).
- **Псевдо-аудит:** при первом заходе в раздел «Редактирование» система
  просит представиться. Имя сохраняется в `created_by` / `updated_by`
  каждой записи.
- **Поддерживаемые таблицы:** все 4:
  - **Закупки** (`procurement`) — 30 полей.
  - **ОС Главная** (`os_main`) — 28 полей.
  - **Пластик** (`plastic_spools`) — 7 полей.
  - **Настройки пластика** (`plastic_settings`) — 5 полей (справочник).
- **Особенности справочника:** `plastic_settings` — без оптимистичной
  блокировки, без аудита, **жёсткое** удаление (DELETE, не soft).
  `plastic_type` уникален: при попытке создать дубликат — ошибка.
- **Переключение между таблицами** — `segmented_control` в начале страницы.

### 7. 🔐 Аутентификация и роли

- **Вход по логину и паролю** (отдельная страница). Пароли хешируются
  через **argon2** — сырые пароли не хранятся.
- **3 роли**:

| Роль | Доступ |
|---|---|
| `viewer` (Наблюдатель) | Поиск, Аналитика, Сканирование. **Только чтение.** |
| `editor` (Редактор) | + Редактирование (CRUD для всех 4 таблиц). |
| `admin` (Администратор) | + Администрирование (импорт из Excel, управление пользователями). |

- **Управление пользователями** (только `admin`): создание, смена пароля,
  смена роли, блокировка / разблокировка.
- **Первый админ** создаётся автоматически при первом запуске
  (`admin` / `admin123`). **Смените пароль** после первого входа.
- **Проверка ролей** — на уровне UI **и** на уровне backend
  (`repositories/*_repo.py` → `require_role`). Даже если `viewer` попытается
  вызвать CRUD через URL — получит `PermissionError`.
- **Аудит** — псевдо-аудит через **«Представьтесь»** (при первом заходе
  в «Редактирование»). Имя сохраняется в `created_by` / `updated_by`.

## ⚡ Инструкция по запуску

### 1. Клонирование репозитория

```bash
git clone https://github.com/BogdanovGleb26/RKKProject.git
cd RKKProject
```

### 2. Создание и активация виртуального окружения

**Windows (PowerShell):**

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope Process
python -m venv venv
.\venv\Scripts\Activate.ps1
```

**Windows (CMD):**

```cmd
python -m venv venv
venv\Scripts\activate.bat
```

**macOS / Linux:**

```bash
python3 -m venv venv
source venv/bin/activate
```

```bash
pip install -r requirements.txt
```

```bash
streamlit run main.py

## 🖼️ Картинки товаров

К карточкам товаров можно привязать **фото предмета** и **картинку QR-кода**.
Картинки лежат локально в папке, путь к которой задаётся переменной
`IMAGES_DIR` в `.env`. Если переменная не задана — используется папка `images/`
рядом с проектом.

### Именование файлов

Связь «карточка ↔ картинка» — по колонке **`Код`** из Excel.

| Файл | Что это | Обязателен? |
|---|---|---|
| `<код>.jpg` | Фото предмета | Нет, но без него — плейсхолдер |
| `<код>_qr.png` | Готовый QR-код (переопределяет генерацию) | Нет — по умолчанию генерируется |

> 💡 **По умолчанию QR-коды не нужно хранить как файлы** — они генерируются
> на лету из колонки `QR код`. Файл `<код>_qr.png` нужен только если хочется
> вручную задать QR, отличный от сгенерированного.

Пример для кода `00000000119`:

```text
images/
├── 00000000119.jpg
├── 00000000119_qr.png
├── 00000000154.jpg
├── 00000000154_qr.png
├── no_photo.jpg ← заглушка, если фото или QR нет
```

### Правила

- `<код>` — **точное** значение колонки `Код` из Excel (с ведущими нулями).
- Поддерживаемые расширения: `.jpg`, `.jpeg`, `.png`, `.webp`.
- Приоритет, если есть несколько файлов с одним кодом:
  `.jpg` > `.jpeg` > `.png` > `.webp`.
- Фото автоматически уменьшается до **800 px** по большей стороне.
- QR показывается **как в файле**, без ресайза.
- `no_photo.jpg` кладётся в ту же папку и используется как заглушка, если
  фото или QR для позиции не найдены.

### Кеш

Картинки кешируются на **5 минут** (как и данные из Excel).
Кнопка **«🔄 Обновить»** в разделе поиска сбрасывает кеш и картинок тоже — если добавили новое фото, нажмите её, чтобы увидеть изменения сразу.

## 🎫 Генерация QR-кодов

QR-коды для товаров **генерируются на лету** из значения колонки `QR код`
в Excel — хранить PNG-файлы не нужно.

### Как это работает

1. Берётся значение колонки `QR код` (например, `МТО00004686138`).
2. К нему добавляется базовый URL формы из переменной `QR_FORM_URL` (`.env`).
3. Полученный URL кодируется в QR-картинку.
4. QR показывается в карточке товара.

При сканировании телефона открывается Google Forms с предзаполненным
значением.

### Настройка

В `.env` добавьте переменную `QR_FORM_URL` — **базовый URL формы**, который
заканчивается на `=`:

```env
QR_FORM_URL=https://docs.google.com/forms/d/e/1FAIpQLSd6.../viewform?usp=pp_url&entry.708913562=
```
> 💡 Если QR_FORM_URL не задан — генерация работать не будет, в карточке покажется плейсхолдер. Ошибки не будет, приложение продолжит работать.

### Приоритет отображения QR

1. Файл <код>_qr.png в папке IMAGES_DIR — если есть.
2. Генерация из значения QR код — если файла нет.
3. Плейсхолдер no_photo.jpg — если ни файла, ни значения.

### Кеш и нагрузка
- Сгенерированные QR кешируются на 5 минут (как и данные).
- Кеш — по значению QR код: две позиции с одинаковым значением получат один и тот же QR из кеша.
- При первом открытии страницы с 50 карточками генерация занимает ~250-500 мс, дальше — мгновенно (кеш).
- Кнопка «🔄 Обновить» сбрасывает кеш QR тоже.

### Параметры генерации
- Размер: ~400×400 px.
- Error correction: M — оптимально для сканирования с экрана.
- Формат: PNG (без потерь).

## 🗄️ PostgreSQL и импорт из Excel

### Зачем нужен PostgreSQL

- **Полноценный CRUD** — добавление, редактирование, удаление позиций.
- **Работа нескольких пользователей одновременно** (SQLite бы «спотыкался»
  на параллельных записях).
- **Оптимистичная блокировка** (`row_version`) — защита от конфликтов.
- **Мягкое удаление** — данные не теряются.

### Настройка PostgreSQL

1. **Установите PostgreSQL** (например, [отсюда](https://www.postgresql.org/download/windows/))
   и DBeaver (клиент для управления БД).
2. **Создайте базу** `rkk_warehouse` (через DBeaver или `psql`).

### Импорт из Excel

Раздел «⚙️ Администрирование» в сайдбаре.

1. Нажмите «🔍 Проверить текущее состояние» — увидите сравнение:

2. Если в БД уже есть данные — появится предупреждение и чекбокс
подтверждения.
3. Нажмите «🚀 Импортировать всё» — данные будут заменены
(TRUNCATE + INSERT).
4. В результатах — статистика: сколько вставлено, сколько пропущено
(пустые строки без code), сколько с ошибками.

Особенности:

- Строки без значения в колонке Код пропускаются (пустые заготовки
в Excel).
- Импорт идёт из текущего выбранного источника (Я.Диск или Локальный ПК).
- Ошибка одной строки не откатывает все остальные (транзакция на строку).

### Схема БД

4 таблицы:
- `procurement` — Закупки.
- `os_main` — ОС Главная.
- `plastic_spools` — Пластик.
- `plastic_settings` — Настройки печати (справочник).

Служебные колонки (во всех, **кроме справочника** `plastic_settings`):
- `id` — автоинкремент.
- `row_version` — для optimistic locking.
- `is_deleted`, `deleted_at`, `deleted_by` — мягкое удаление.
- `created_at`, `updated_at`, `created_by`, `updated_by` — псевдо-аудит.

**Справочник `plastic_settings`** — без служебных колонок:
- Только `id` + 5 бизнес-полей.
- Жёсткое удаление.
- `plastic_type` — UNIQUE.

## 🔒 Оптимистичная блокировка (optimistic locking)

Для предотвращения конфликтов при одновременном редактировании
используется колонка `row_version`:

- При **открытии** формы «Редактировать» фиксируется текущая `row_version`
  (сохраняется в `session_state`).
- При **сохранении** выполняется:
  ```sql
  UPDATE ... WHERE id = :id AND row_version = :expected_version
- Если row_version в БД изменилась (кто-то сохранил раньше) — 0 строк → показывается ошибка: «Позиция изменена другим пользователем...».
- row_version увеличивается на 1 при каждом успешном UPDATE.

Что не защищено: справочник plastic_settings (там нет row_version).
Для справочника конфликты маловероятны (5 полей, редко меняется).

## 🔐 Аутентификация и роли

### Первый запуск

При **первом** запуске приложения (если в `users` нет ни одного `admin`)
**автоматически** создаётся:

- **Логин:** `admin`
- **Пароль:** `admin123`

**⚠️ Смените пароль** сразу после первого входа:
1. Войти как `admin` / `admin123`.
2. «Администрирование» → «👥 Пользователи».
3. У пользователя `admin` → «🔑 Сменить пароль».

### Роли

| Роль | Поиск | Аналитика | Сканер | Редактирование | Администрирование |
|---|---|---|---|---|---|
| `viewer` | ✅ | ✅ | ✅ | ❌ | ❌ |
| `editor` | ✅ | ✅ | ✅ | ✅ | ❌ |
| `admin` | ✅ | ✅ | ✅ | ✅ | ✅ |

### Управление пользователями

Доступно только `admin`. В разделе «Администрирование» → **«👥 Пользователи»**:

- **Список** всех пользователей (логин, роль, статус).
- **➕ Создать пользователя** — логин, пароль, роль.
- **🔑 Сменить пароль** — у любого пользователя.
- **✏️ Сменить роль** — у любого (**кроме** себя).
- **🚫 Блокировать / ✅ Разблокировать** — (**кроме** себя).

**Заблокированный** пользователь:
- Не может войти (ошибка «Учётная запись заблокирована»).
- Если он был в системе — при следующем logout не сможет войти.

### Безопасность

- **Пароли** — только `argon2`-хеш (сырые **не хранятся**).
- **Проверка ролей** — **дважды**:
  - **UI** — скрытие недоступных вкладок.
  - **Backend** — `require_role` в `repositories/*.py` (даже прямой вызов CRUD из кода вернёт `PermissionError`).
- **Сессии** — `session_state` (**не переживает** перезагрузку страницы → повторный вход). **Для пилота** — приемлемо.
- **`created_by` / `updated_by`** — псевдо-аудит через **«Представьтесь»**. **Имя** вводится **один раз** при первом заходе в «Редактирование», сбрасывается при logout.

### Смена роли / пароля — **не в реальном времени**

- **Роль:** смена роли **применяется** после **logout / login** пользователя.
- **Пароль:** смена пароля **применяется** сразу при **следующем** входе.
- **Блокировка:** действует **сразу** (при попытке **нового** входа).

## 🔄 Обновление данных
- Данные кешируются на 5 минут (`@st.cache_data(ttl=300)`).
- Кнопка «🔄 Обновить» есть в разделах:
  - **Поиск** — сбрасывает `load_data` (Excel), `fetch_df` (PostgreSQL),
    кеш картинок и QR.
  - **Аналитика** — сбрасывает `load_data` и `fetch_df`.
  - **Редактирование** — сбрасывает `fetch_df` (только PostgreSQL).
- При смене источника данных в сайдбаре кеш также сбрасывается автоматически.
- После любой CRUD-операции (добавление / редактирование / удаление)
  кеш PostgreSQL сбрасывается автоматически.

## 🗺️ Планы развития
- **Полный аудит** — таблица `audit_log` (кто, что, когда менял).
- **Периодический импорт из Excel** — сейчас TRUNCATE+INSERT, что
  удаляет CRUD-данные. Нужен безопасный механизм (upsert по `code`).
- **Бэкапы БД** — автоматический `pg_dump` по расписанию.
- **Расширенная аналитика** — доработка метрик под реальные требования.
- **Улучшенный UX для мобильных** — дальнейшая оптимизация.
- **Автокомплит в формах** — подсказки по `mto_department`, `mto_curator`,
  `project` и т.д. на основе существующих значений.
- **История изменений в UI** — просмотр изменений из `audit_log` в карточке.
- **Смена роли / пароля в реальном времени** — сейчас только после logout/login.
- **Cookie-сессии** — чтобы вход не терялся при перезагрузке страницы.
- **`super_admin`** — отдельная роль для управления другими админами.
